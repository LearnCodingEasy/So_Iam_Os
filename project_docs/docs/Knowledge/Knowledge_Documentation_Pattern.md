# 📚 Knowledge Documentation Pattern

> Standard Pattern for Converting Technical Information into Structured Knowledge Documentation.

---

# 1. 🎯 Purpose

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

الهدف من هذا الملف هو تحديد الطريقة الموحدة التي يتم استخدامها لتحويل أي معلومة أو شرح أو ملاحظات تقنية إلى ملف Knowledge Documentation منظم وقابل للقراءة والرجوع إليه.

</div>

---

# 2. 🧠 Concept

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

أي معلومة يتم تحويلها إلى Knowledge يجب أن تكون أكثر من مجرد مجموعة أوامر أو أكواد.

يجب أن توضح المعلومة: ما هو الموضوع، ولماذا نستخدمه، وكيف نستخدمه، وما الأخطاء الشائعة فيه، وكيف يتم استخدامه داخل المشروع، وما المعلومات التي يحتاج الـ AI إلى معرفتها عنه.

</div>

---

# 3. 🔧 Requirements

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

قبل إنشاء ملف Knowledge جديد، يجب تحديد الـ Technology أو Topic الذي يتحدث عنه الملف، ومعرفة علاقته بالمشروع إذا كانت موجودة.

</div>

---

# 4. 🛠️ Installation / Setup

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

هذا القسم يستخدم لتوثيق خطوات التثبيت والإعداد والأوامر المطلوبة لبدء استخدام الـ Technology أو Topic.

يتم الحفاظ على الأوامر البرمجية داخل Code Blocks، بينما يتم وضع الشرح العربي خارجها داخل RTL HTML Block.

</div>

---

# 5. 🚀 Usage

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

هذا القسم يوضح كيفية استخدام الـ Technology أو Topic عمليًا، مع أمثلة وأوامر حقيقية عند الحاجة.

</div>

---

# 6. 📁 Structure

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

هذا القسم يستخدم لتوضيح شكل الملفات والمجلدات أو Architecture الخاصة بالموضوع.

</div>

```text
Project/
│
├── folder/
│   ├── file.py
│   └── ...
│
└── ...
```

---

# 7. 🧩 Important Concepts

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

يتم وضع أهم المفاهيم والمصطلحات المرتبطة بالموضوع هنا، مع توضيح وظيفة كل مفهوم وعلاقته بباقي المفاهيم.

</div>

---

# 8. 💻 Examples

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

يتم وضع أمثلة عملية توضح استخدام الموضوع، مع الحفاظ على الكود والأوامر داخل Code Blocks.

</div>


<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

يتم توثيق الأخطاء الشائعة التي يمكن أن تحدث أثناء استخدام الموضوع، مع توضيح سبب الخطأ والطريقة الصحيحة لتجنبه.

</div>

---

# 10. 🧠 Why?

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

يجب توضيح السبب وراء كل خطوة مهمة، وليس الاكتفاء بتوضيح كيفية تنفيذها.

الهدف هو فهم القرار التقني وليس حفظ الأوامر فقط.

</div>

---

# 11. 🔗 Project Usage

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

يتم توضيح مكان استخدام الـ Technology أو Topic داخل مشروع So_Iam_OS، وما علاقته بالـ Architecture أو التطبيقات أو المكونات الأخرى.

</div>

---

# 12. 🤖 AI Reference

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

هذا القسم مخصص للمعلومات التي يحتاج الـ AI إلى معرفتها عند التعامل مع هذا الموضوع داخل المشروع.

يجب أن يحتوي على الـ Context والقواعد والافتراضات المهمة، وما يجب على الـ AI فعله أو تجنبه.

</div>

# 🎨 Documentation Styling Rules

## 📝 Arabic Text

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

أي شرح أو نص عربي وصفي داخل Knowledge Documentation يجب أن يتم وضعه داخل HTML Block باستخدام الاتجاه من اليمين إلى اليسار وحجم خط 1.3rem وخط عريض.

</div>

```html
<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">
  النص العربي هنا
</div>
```

---

## 💻 Code

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

الكود والأوامر لا يتم وضعها داخل RTL HTML Block، وإنما يتم استخدام Markdown Code Fence للحفاظ على تنسيق الكود وقابليته للنسخ.

</div>

```cmd
python --version
```

---

## 📁 File Structure

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

هياكل الملفات والمجلدات يتم وضعها داخل Code Fence باستخدام نوع `text`.

</div>

```text
Project/
├── app/
├── manage.py
└── ...
```

---

## 📊 Tables

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

الجداول يتم كتابتها باستخدام Markdown Table، ولا يتم وضعها داخل RTL HTML Block.

</div>

| Item   | Status |
| ------ | ------ |
| Python | ✅     |
| Django | 🔄     |

# 🤖 AI Documentation Rules

<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">

عند طلب المستخدم تحويل أي محتوى إلى Knowledge Documentation، يجب استخدام هذا الملف كـ Standard Pattern.

يجب الحفاظ على الأقسام الستة عشر وترتيبها.

يجب الحفاظ على الأكواد والأوامر التي يقدمها المستخدم وعدم حذفها.

يجب إضافة شرح واضح للمعلومة بدون تغيير معناها.

يجب وضع النص العربي داخل:

`<div dir="rtl" style="font-size: 1.3rem; font-weight: bold;">`

بينما يتم إبقاء Code Blocks وTables وFile Structures خارج الـ HTML Block.

يجب ربط المعرفة بالمشروع عندما تكون المعلومة مرتبطة بالمشروع.

يجب استخدام قسم `AI Reference` لتوثيق المعلومات والقواعد التي يحتاجها الـ AI.

يجب عدم اختراع حالة للمشروع. إذا كانت الحالة غير معروفة، يتم توضيح ذلك بدل افتراضها.

</div>
